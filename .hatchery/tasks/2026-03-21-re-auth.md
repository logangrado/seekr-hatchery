## Objective

With `oauth` workflows (e.g. claude), we need a way to fetch a new token if the URL returns a 401.

For both `claude` and `codex`, we can do this by firing off a short test query in the background (e.g. "claude hello", or "codex hello").

This forces a new token, which will get written.

To support this, we need a mechanism in `proxy` where:

- When a 401 is detected, it calls `header_mutator(headers, refresh=True)`. This lets the bakend then take care of a refresh attempt, and then returning new headers.

## Summary

**Files changed:** `proxy.py`, `agent_backend.py`, `agents/claude.py`, `agents/codex.py`, `tests/test_proxy.py`

**Key decisions:**
- `_handle_request` takes a `_retried: bool = False` kwarg; on upstream 401 it drains the body, calls `header_mutator(pre_auth_headers, refresh=True)`, opens a fresh connection, and retries once. The retry result is forwarded unconditionally.
- `start_proxy` type annotation changed to `Callable[..., dict[str, str]]` to allow the optional `refresh` kwarg.
- `make_header_mutator()` return type updated in `AgentBackend` ABC and both backends to `Callable[..., dict[str, str]]`.
- Both backends now use a mutable `state` dict + `threading.Lock` to allow the token to be updated safely across concurrent proxy threads.
- Claude refresh: fires `claude hello` as a subprocess, polls `_read_claude_creds()` every 0.5 s for up to 30 s or until the process exits. Updates `state["token"]` only if a *different* token is found.
- Codex refresh: same pattern but polls `auth_file.stat().st_mtime` (faster, avoids repeated JSON parsing) then does a single credential read on change.
- For `API_KEY` sources, `refresh=True` is a no-op — API keys don't expire.
- Test helpers updated to accept `**kwargs` so they survive `header_mutator(h, refresh=True)` calls. `TestProxyReauthOn401` adds three cases: successful retry, double-401 forwarded, non-401 not retried.
